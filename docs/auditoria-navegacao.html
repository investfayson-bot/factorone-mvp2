01

O diagnóstico: dois menus disputando o mesmo espaço

A sidebar é montada por duas lógicas ao mesmo tempo — e é daí que vem a sensação de coisa repetida e de "plugin solto".

Hoje o menu (app/dashboard/layout.tsx) mistura grupos fixos escritos no código (Gestão financeira, Contabilidade, Banco…) com grupos criados dinamicamente pelos apps instalados do marketplace (lib/marketplace.ts). Como cada app declara seu próprio navGroup, nascem grupos paralelos que fazem quase a mesma coisa que os fixos.

Causa-raiz

Existe um grupo fixo "Gestão financeira" e, ao lado, um grupo "Financeiro" gerado pelos apps. O mesmo acontece com "Contabilidade" × "Contabilidade & Fiscal". São quatro grupos para duas ideias. E funções que deveriam ser abas de uma solução (agendamento, follow-up, propostas) viram itens avulsos porque cada uma é um "app".

O usuário nunca escolhe entre dois menus parecidos. Ele escolhe uma solução e, dentro dela, navega por abas que contam uma história (o dinheiro entra → é classificado → vira relatório). O marketplace continua existindo — mas para ligar/desligar capacidades, não para virar item de menu solto.
O que muda no código (barato)

O navGroup de cada app passa a apontar para uma das 6 soluções (ex.: agenda, posvenda, crm → todos navGroup: 'Clientes & Vendas'). Some os grupos fixos duplicados de buildNavGroups(). As páginas já existem — é reorganizar o menu e adicionar uma faixa de abas no topo de cada solução. Preservar o controle por papel (GRUPO_ROLES) e o corte por segmento (hidePatrimonio).

03

O Banco, com a cara de um app de banco

A prioridade — é o que roda de verdade agora, via Open Finance. A meta: quando a pessoa conecta o banco, ela sente que abriu o C6 / BTG / XP. Uma home só, com o dinheiro todo agregado.

A distinção que define o escopo

O Open Finance (Belvo) que temos hoje é leitura e agregação. Isso significa que dá pra entregar a experiência visual idêntica a um app de banco agora — ver saldo, extrato, faturas, investimentos. Já o que age no dinheiro (bloquear cartão, cartão virtual, PIX saindo da conta) depende da conta própria FactorOne — a 2ª etapa, quando as APIs de emissão estiverem prontas. A home abaixo mostra as duas camadas: o que é real hoje e o que entra depois.
